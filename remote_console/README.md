# 灌溉远程控制台

这是运行在 Mac 上的本地网页控制台。浏览器只访问本机 `127.0.0.1`，本地服务通过 TLS 连接公网 MQTT Broker，不需要 Home Assistant。首页、运行态、手动浇水和计划管理直接采用 ESP32 本地 Web 的同一套内容、状态优先级、过滤、确认和响应式结构；远程入口不包含校准、区域基准、系统设置、日志、OTA 和完整记录列表。

## 使用

1. 首次使用双击 `首次安装.command`。
2. 双击 `启动灌溉控制台.command`。
3. 浏览器会自动打开 `http://127.0.0.1:8787/`。
4. 保持启动控制台的终端窗口开启；关闭终端即停止本地服务。

也可以在终端运行：

```sh
cd remote_console
npm install
npm start
```

## 日常操作

- 首页显示当前运行阶段、水路进度、剩余时间、当前与预期流量、估算水量、下一计划、最近任务、设备时间和故障原因。
- “手动浇水”只列出设备当前启用的水路；可套用任一已保存计划后临时修改，不会改动原计划。
- “计划管理”只显示已配置计划；自动执行关闭的计划仍可作为手动模板。新增计划自动使用首个空槽。
- 自动浇水总控只显示当前可执行的动作。定时暂停需要设备时间可信；设备时间未就绪时仍允许无限期暂停。
- 手动启动、停止整次浇水、暂停自动浇水和删除计划都有确认。操作提交期间按钮会锁定，最终以设备回执和随后状态为准。
- 时长上限和禁用水路均来自设备当前配置，前端和本地服务各校验一次。

## 配置

非敏感配置在 `config.json`：

- `deviceId`：ESP32 的设备 ID。
- `listenPort`：本地网页端口，默认 `8787`。
- `commandTimeoutMs`：等待设备确认命令的最长时间。

MQTT 地址、TLS CA 和凭据继续读取 `firmware/platformio.local.ini`，不会复制到网页或仓库。当前可临时复用设备账号；正式长期使用建议在该文件增加：

```ini
custom_irrigation_console_mqtt_username = 控制台专用用户名
custom_irrigation_console_mqtt_password = 控制台专用密码
```

控制台专用账号只应具有目标设备主题的订阅权限，以及 `irrigation/{deviceId}/command` 的发布权限。私密配置与证书已由项目 `.gitignore` 排除。

## 安全边界

- HTTP 服务只监听 `127.0.0.1`，同一局域网的其他设备不能直接访问。
- 每次启动生成随机页面会话令牌，写操作还校验来源。
- MQTT 使用 TLS 并校验服务器证书。
- 控制命令使用 QoS 1，并以设备 `result` 应答为最终结果。
- 设备离线或业务未就绪时，控制操作会被锁定；页面根据 MQTT `ready_reason` 展示文件系统、配置或启动检查的具体失败原因，不把未就绪误报为漏水。
- 页面明确区分业务未就绪、设备时间未就绪、RTC 降级、关阀后水流异常和存储故障；不会用一个模糊提示代替具体原因。
