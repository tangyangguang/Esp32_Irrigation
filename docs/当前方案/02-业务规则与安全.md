# 02 业务规则与安全

## 术语约定

方案和界面统一使用以下名称：

| 名称 | 含义 |
| --- | --- |
| 控制器 | 当前 ESP32 单板设备 |
| 区域 | 一路电磁阀控制的浇水范围；英文资料常称 Zone 或 Station |
| 浇水计划 | 一组区域运行时长，可手动执行，也可选择参加每日定时调度 |
| 自动执行 | 单个计划是否参加每日定时调度，不影响手动选择该计划 |
| 暂停自动浇水 | 暂时阻止全部计划自动启动的总控状态，不影响手动浇水 |
| 启动时间 | 一个计划每天开始执行的时间 |
| 区域运行时长 | 计划中某个区域每次浇水的时间 |
| 基准流量 | 某个区域通过流量学习并确认保存的正常预期流量 |
| 手动浇水 | 用户立即启动一次浇水操作 |
| 流量报警 | 无流量、低流量、高流量或关阀后水流异常 |
| 浇水记录 | 实际发生过的浇水业务数据 |
| 事件 | 需要追溯的重要动作、报警和异常信息 |

后续软件设计可以使用英文代码名称，但必须与这些产品概念一一对应，不能为了代码结构再创造一套用户难以理解的概念。

## 区域

- 控制器固定管理 6 个区域。
- 默认启用区域 1、区域 2；区域 3 至区域 6 默认停用。
- 用户可以修改水路名称和启用状态；名称去除首尾空白后为 1–20 个 Unicode 字符且 UTF-8 编码不超过 63 字节，不接受 U+0000–U+001F 和 U+007F 控制字符。
- 基准流量没有默认值，可以通过真实出水学习，也可以由用户按 `L/min` 手工设置。内部统一保存 `P/s × 10000` 的高精度原始基准脉冲速率，`0` 表示未设置；页面使用当前稳态流量系数动态换算并以三位小数的 `L/min` 显示。手工输入保存前必须完成定点换算和三位小数回算校验，例如输入 `20.000 L/min` 后必须仍回显 `20.000 L/min`，不另存只用于显示的重复字段。用户可以重新学习、手工修改或清除基准。
- 停用区域不出现在手动浇水和计划时长表中。
- 已保存的区域时长在区域停用后继续保留，重新启用后可以继续使用。
- 如果停用区域会使某个开启自动执行的计划失去全部可运行区域，本次保存应拒绝并指出受影响计划；用户先关闭该计划的自动执行或调整计划后再停用区域。没有开启自动执行的计划可以保留为暂时不可运行状态。

## 浇水计划

- 最多保存 8 个计划。
- 一个计划包含名称、自动执行开关、最多 4 个每日启动时间和各区域运行时长；已配置计划的名称使用与区域名称相同的长度和编码规则。
- 当前周期固定为每天。
- 区域运行时长按整分钟配置；`0` 表示不执行，非零值为 1 分钟至当前“单水路最长运行时间”。
- 至少包含一个当前启用区域的非零时长，才是可运行的已配置计划；只用于手动运行时可以不设置启动时间。
- 关闭自动执行的计划保留全部配置且不参加定时调度，但仍可被用户手动选择并立即执行。
- 所有开启自动执行的启动项在全局范围内不能使用相同时间，包括同一计划的多个启动项，避免同一分钟产生不明确的执行顺序；开启开关时必须同时校验冲突。
- 修改计划只影响之后的浇水，不改变已经开始的浇水操作。

多个启动时间表示同一组区域时长每天执行多次。如果不同时段需要不同的区域时长，应建立不同计划。

## 手动浇水

手动浇水只有一个入口：首页“手动浇水”按钮打开的弹层（不跳转独立页面）。每条启用水路一行，可单独选择“按时长”或“按水量”；每行数值填 0 表示该水路本次不执行，不单独设置“不执行”控件。提交后只运行数值大于 0 的水路，按水路编号顺序执行，一次任务中允许时长行与水量行混排。只给一条水路设置非零值就是单条手动浇水，不需要另一种运行模式。

按时长以整分钟填写，不提供秒级输入；按水量以 L 输入，步进 0.1 L，mL 定点整数保存，上限由运行限制决定。弹层可以选择任意一个已配置计划作为时长模板，点击后把计划中当前启用水路的分钟时长填入并复位为按时长；用户仍可逐行修改或改为按水量，修改不会保存回计划。系统只按最终提交的各水路内容执行和记录，不把模板计划保存为本次浇水来源。弹层底部汇总已选水路数、时长合计和按水量条数，并按安全时限给出全程最长用时的粗算提示；提交失败时弹层保持打开并回填刚才的内容。

## 按水量手动浇水

按水量是手动浇水弹层中每条水路的次级目标方式，不单设“单次出水”业务来源、页面或水路页工具；本地 Web 也没有独立“单次出水”入口或独立按水量页面。

每个按水量步骤同时携带该水路的最长运行时间作为安全时限。达到估算水量后该路正常结束；先达到时限仍未达水量则该路失败并结束整个任务，记录中明确原因。它复用同一阀泵顺序、无流量保护、流量偏差保护、互斥和结束记录。计量系数、阀门响应和余流会影响结果，不承诺精确计量。

## 运行规则

- 同一时刻只执行一次浇水操作。
- 一次浇水可以包含多个区域，但同一时刻只打开一个区域。
- 当前区域结束并安全关闭后，等待配置的水路切换间隔，才启动下一区域；间隔期间水泵和全部区域阀保持关闭。
- 设备正在浇水或学习时，新的手动请求直接拒绝并说明原因。
- 自动计划到点但未能启动时，本次计划跳过并记录具体原因，包括正在手动浇水、另一自动计划正在运行、正在学习基准流量、上一任务正在收尾、功能未就绪、计划配置无效或控制输出启动失败。
- 错过的计划不补执行。
- 用户可以随时停止当前浇水。
- 普通单区域最长运行时间由系统参数配置，默认 120 分钟，范围 1–720 分钟。该上限同时约束自动计划、按时长与按水量手动浇水；基准流量学习使用独立的维护时限。
- 区域运行时长从流量建立后的正常浇水阶段开始计算，不包含阀启动、泵启动延时和流量建立时间。

启用自吸泵时，单个区域按以下顺序运行：

1. 打开区域阀。
2. 输出自吸泵干接点控制信号。
3. 等待泵启动延时。
4. 等待流量建立。
5. 开始区域运行时长计时和流量监测。
6. 结束时先取消泵控制信号。
7. 等待停泵后关阀延时。
8. 关闭区域阀。

阀的全功率吸合和转入维持占空比由阀驱动独立计时，不额外推迟泵控制信号。

## 流量监测与报警

### 无流量报警

无流量报警是所有出水过程的基本保护，包括普通浇水和区域流量学习。

- 打开区域并完成泵启动延时后开始等待流量建立；在流量建立超时内没有检测到有效脉冲，停止整次浇水。
- 流量已经建立后，运行途中连续没有有效脉冲达到运行中无流量超时，同样停止整次浇水。
- 停止时关闭泵控制信号和区域阀，原因保存在本次浇水结果中。

默认流量建立超时为 20 秒，运行中无流量超时为 10 秒。启动阶段直接使用一个总超时，不把同一件事拆成“宽限”和“确认”两个参数。自吸泵实物测试时必须确认启动超时不会造成不可接受的干抽风险。

### 低流量和高流量报警

低流量和高流量直接比较当前原始脉冲速率与区域基准脉冲速率，不依赖稳态流量系数。区域没有有效基准流量时，这两项监测不启用，无流量保护仍然有效。

- 默认低流量阈值：基准流量的 30%。
- 默认高流量阈值：基准流量的 200%。
- 默认持续确认时间：20 秒，按连续异常流量窗口的实际时长累计；任一正常窗口会清零本次累计。
- 默认动作：只报警，当前浇水继续。
- 可选动作：报警并停止整次浇水。
- 首次连续偏差达到确认时间时立即显示当前报警，不等待当前水路或整次浇水结束。若动作是继续浇水，之后连续正常达到同一确认时间则当前报警状态恢复；后续再次连续偏差可以再次进入报警状态。

系统只有一个总流量计，不能可靠判断异常来自当前末端、公共供水还是主管路，因此当前不设计自动隔离故障区域后继续浇水的复杂诊断流程。

同一区域一次运行中的高低流量判断实时显示，最终记录保留是否曾经发生的标志和当时基准；不再复制为一组独立技术事件。

这些阈值是未取得现场基准数据前的保守初始值。完成区域流量学习后，应结合水塔水位变化、实际管路和阀门测试结果调整，不能把默认值视为通用行业标准。

### 关阀后水流报警

所有区域阀和泵控制信号都关闭后仍检测到持续水流，称为关阀后水流异常。它可能由漏水、阀未完全关闭、管路余流、上游其它用水或流量计干扰引起，不能直接描述为已经漏水。

- 全部输出关闭后先等待配置的检测延时，默认 30 秒，再开始关阀后水流检测，避免管路余流造成误报警。关阀和监测器复位必须使用同一单调时间快照，不能因一次业务循环内的时间先后产生回绕并绕过延时。
- 默认检测窗口：30 秒。
- 默认阈值：窗口内 3 个脉冲。
- 达到阈值后显示“关阀后水流异常”，并记录一次发生事件。
- 报警后，连续一个完整检测窗口没有任何脉冲才解除报警；不为恢复条件增加单独配置。
- 报警没有恢复前不重复写入相同事件；恢复时记录一次恢复事件。
- 该报警只提示，不自动打开或关闭其它设备。

## 自动调度

- 自动浇水总控默认为正常运行。暂停只有“暂停至恢复时间”和“无限期暂停”两个结果。
- 定时暂停的最终输入是 UTC+8 恢复时间。页面直接选择恢复日期和时间，不保存额外倒计时状态。
- 保存时只把最终恢复时间换算为 `resumeAtEpoch`，不另行维护小时数或易受重启影响的倒计时。
- 时间不可信或发生 RTC 倒退时只能选择无限期暂停；设置恢复时间必须等待时间恢复可信。手动恢复不受时间状态影响。
- 设置定时恢复必须以可信时间为前提；时间失去可信状态时继续保持暂停，直到时间重新可信且已经到达恢复时刻。
- 暂停只阻止之后的自动计划，不停止已经开始的浇水，也不影响任何手动浇水方式。
- 暂停期间到点的计划直接跳过且不补执行。系统仍将相应启动项记为已处理，但不为每个跳过项重复写事件。
- 用户暂停、用户恢复和到期自动恢复记录事件。暂停原因属于用户决定，当前不设计天气等自动暂停来源。
- 产品时间按 UTC+8 使用，不使用夏令时。
- 自动计划只在时间可信时运行；本地日期早于 2026-01-01、RTC 状态异常且没有 NTP 时间时，均视为时间无效。
- 系统无法自行判断几分钟以内的实际误差，只显示当前时间来源是 RTC 还是 NTP。
- 只有 RTC 时间比设备最后一次可信时间倒退超过配置阈值时，才显示“RTC 时间倒退”并停止自动调度；默认阈值为 5 分钟，可以在系统参数中修改。
- NTP 成功校时后以 NTP 为准并解除“RTC 时间倒退”；用户主动暂停自动浇水的状态不受影响。
- 控制器启动时所在的当前分钟不触发计划，避免重启落在启动时间内造成重复浇水。
- 时间首次变为可信，或本地分钟不是按正常连续顺序进入时，只重新建立调度检查点，不触发跳变后落入的当前分钟。
- 时间向前调整时不补执行已经跳过的时间。
- 时间向后调整时，同一个启动时间当天最多执行一次。
- 重启后仍需保证当天已经处理过的启动时间不重复执行。
- 时间无效时，手动浇水仍可使用；下一次计划和今日统计显示为不可用。

当天已处理标记的保存和防重复方式见 `03-软件设计原则与边界.md`。

## 设备启动与掉电估算

- 每次设备启动及其复位原因使用 `Esp32Base` 系统日志记录，不在业务事件中重复保存。
- 当前硬件不能在突然断电后继续写入，因此不能记录精确断电时间，只能保存“最后一次确认在线”的时间并估算范围。
- 存活检查点默认间隔为 12 小时，可以按小时配置；`0` 表示关闭周期检查点。
- 浇水记录或事件已经提供了更新的可信时间时，重新计算检查点间隔，不额外写入检查点；浇水过程中也不周期写入。
- 新启动时结合上次确认在线时间、检查点间隔和本次启动时间显示可能断电时间及可能停电时长范围，不能显示成精确结论。
- 时间无效或启动原因不是可能掉电时，只显示已知事实，不估算停电时长。

## 流量校准与学习

### 计量参数

设备只消费一个参数 K（每升脉冲数，P/L）：水量 L=P/K。设置入口使用 Base App Config，允许两位小数，NVS 与内存保存 X100 整数。默认 250.00 P/L；不是对任意流量计精度的保证。

专业采样、启动/稳态分析、多流速拟合与小程序校准是独立后续任务。本固件不保留校准工作台、样本、启动补偿或未定采样 API。参数更新只影响后续任务，已经开始的任务使用启动时快照；基准流量学习以原始脉冲速率保存，不因 K 修改而失效。

### 区域流量学习

目的：学习某个区域正常浇水时的基准流量，用于低流量和高流量报警。

1. 启动目标区域。
2. 等待流量建立；该阶段不参与计算。
3. 每 5 秒生成一个原始脉冲速率窗口，保留最近 5 个窗口；页面每秒刷新运行时间、按当前校准系数换算的最近流量、窗口平均值、最大值、最小值和有效窗口数。
4. 至少取得 5 个有效窗口。
5. 每个窗口必须至少有一个脉冲；最近窗口最大值与最小值之差不超过平均值的 10% 和一个脉冲量化误差两者中的较大值时认为稳定。
6. 使用最近 5 个窗口的总脉冲数和总时间计算建议基准脉冲速率，用户确认后保存。保存、放弃、重新学习和清除基准都由用户明确操作。

流量学习保留无流量保护，不执行低流量和高流量报警。离开页面不会自动停止；从开阀开始最多运行 10 分钟，达到上限仍未稳定时自动停止并提示重新检查供水条件。稳定结果由用户选择保存或放弃。仅修改稳态流量系数不会使已学习基准失效；更换流量计、喷头、阀门、管路或改变正常供水条件后必须重新学习受影响水路。

| 低/高流量动作 | 只报警 | 只报警或停止整次浇水 |

250.00 P/L 是首次使用的默认稳态流量系数。基础库 App Config 页面保留两位小数，NVS 和内存使用放大 100 倍的整数保存，例如 `250.37` 保存为 `25037`。用户填写外部校准得到的每升脉冲数；系统只保存当前系数，不维护额外的校准状态。

按脉冲数估算水量时使用 64 位整数计算：`估算水量 mL = 四舍五入(脉冲数 × 100000 ÷ 放大后的系数)`。这样只处理一次比例，既保留两位小数，也避免中间乘法溢出和浮点累计误差。

## 浇水记录与事件

### 浇水记录

浇水记录是已经被设备接受并进入执行流程的普通浇水业务数据。本项目定义其字段、业务校验、分页、列表和详情，底层保存、最新优先读取、轮换、损坏检查和逻辑清空使用 `Esp32BaseRecordStore`。用户清空统一从 `Esp32Base` System 页的 `Clear Business Records` 执行，业务页面不提供平行入口，也不提供记录导出。

记录至少能够回答：

- 什么时间浇水。
- 来源是手动还是计划。
- 执行了哪些区域。
- 每个区域计划运行多久、实际运行多久。
- 每个区域有效浇水阶段的整段平均流量、当时基准流量、是否出现过高低流量、记录了多少脉冲、估算用了多少水。
- 任务总历时、计划浇水总时间、实际浇水总时间、触发高低流量报警的水路数、总脉冲数和历史估算总水量。
- 是否正常完成，为什么提前结束。

普通浇水请求只要已经被设备接受并进入执行流程，无论正常完成、用户停止、启动阶段未检测到水流、运行中水流中断或其它异常停止，都必须在会话结束时产生一条浇水记录。请求参数无效、设备忙或其它启动前拒绝不属于浇水记录；自动计划未能启动时使用计划跳过事件表达。流量学习不写普通浇水记录。

整次历时由记录基础元数据提供；其余总计在读取时从 6 个区域明细求和，不在 Flash 中重复保存。历史估算总水量汇总各区域当时已经保存的估算水量；按当前稳态流量系数重算的水量只能作为明确标注的参考值。总脉冲和总水量使用 64 位整数汇总，避免相加溢出。

整段平均流量使用水流建立后到有效浇水阶段结束之间的总脉冲除以实际毫秒时长，不把等待水流建立、停泵后关阀延时和关闭尾水混入。它表达整段用水强度，不等同于最终稳定流量。

末段流量和稳定性用于运行期判断，当前紧凑历史不保存这些窗口汇总；历史页面只展示已保存事实，不能根据整段平均伪造末段数据。

### 审计与持续条件

普通浇水的成功、失败、停止仅保存一条 watering 结果；自动计划已执行不重复产生“自动运行事件”。未接受的自动计划保存具体跳过原因。必要操作记录保存自动总控暂停/恢复、计划/水路/参数修改、基准保存，以及关阀后持续水流的发生/恢复，位于独立 irrigation-audit Store。启动、网络、OTA 及底层故障诊断仍使用成熟的 FileLog。

硬件时钟、可信时间、时间倒退和关阀后水流的当前状态由观察结果推导。Conditions 只在 RAM 中确认状态，重启后重新观察；未知不能显示成正常，不建立另一套持久事件系统。当前异常在首页就地展开原因与影响，必要历史在记录页的次级入口查看。

### 滚动保留、重启与统计口径

本地历史采用**基于字节预算的分段滚动保留**：新记录需要空间时淘汰最早的完整段，不以是否同步为淘汰条件。容量不是固定条数承诺；正常轮转不得阻止任务。真实文件写入、CRC 或任务标记故障需明确提示，不能虚报记录成功。

正常任务在启动输出前保存小型持久任务标记；输出关闭后先追加最终结果，再清除标记。重启时保持全部输出关闭，已有最终结果不重复追加；只有开始标记而无结果的任务补记“运行中断、结果不完整”，实际进度、时长和水量均未知，不自动续浇。接受前拒绝不生成普通浇水记录；接受后即使开阀失败也留下失败结果。

每日卡片首先显示实际浇水时长，其次显示实际出水次数，水量是次要估算信息。次数按水路确有脉冲的任务计数；失败/停止但已经出水的任务也计入已知时长和用水，同时标明异常。结果不完整不伪造零值。当前任务暂计且标记进行中。按各水路开始日期归属，跨日不拆分；无可信开始时间的记录保留但不强行归入某天。较早历史淘汰后，受影响日期提示统计可能不完整。

## Web 信息结构

| 页面 | 用户目的与内容 |
| --- | --- |
| 首页 | 每日分水路时长、次数、次级水量；前后日期及日期选择；下一次自动浇水；有影响的当前异常。运行时首先显示当前任务和停止操作。手动入口低强调。 |
| 手动浇水 | 首页弹层；每条水路可选按时长或按水量、允许混排，可从计划填入时长。只影响本次任务。 |
| 计划列表 / 编辑 | 自动总控、暂停与恢复、每日计划；列表与编辑分开，保存不立即出水。 |
| 记录 / 详情 | 按日期、水路和结果筛选；结果原因、实际与目标时长、估算水量、各水路平均/基准流量直接显示；沿用旧版列表和详情弹窗，原始计量依据位于次级说明区。 |
| 设备设置 | 水路维护、基准学习、系统参数及 Base 诊断/维护入口。水路页采用紧凑列表，点击“修改”打开单条水路表单；基准维护保留独立入口，不平铺全部编辑表单。 |
| 操作与设备异常历史 | 次级页面，用完整中文说明计划跳过、配置变化和需要追溯的异常，避免裸枚举及无说明技术字段。 |

页面以 b831ee3（本地核心重构前）的原有风格、组件和布局为基准，不再引入新的全局主题。新信息使用原组件承载；计划、水路和记录保留原有列表/详情与编辑弹窗。手动浇水为首页弹层，每条水路一行并可逐行选择按时长或按水量，不提供独立手动页或独立单次出水页；设备设置复用 Base 面板和入口样式。只因最新业务逻辑调整字段、入口和状态说明，禁止卡片左侧彩色竖条。编辑失败保留主要输入；成功后重定向避免刷新重发。动态状态页在隐藏时暂停轮询，网络失败显示过时提示并退避，不把断连当任务结束。

所有操作仍使用 Base 的 Web 认证、POST 来源检查和维护门禁。浇水/学习活动中拒绝 OTA 与格式化，OTA 期间拒绝新任务。重启先关闭输出。文件系统不自动格式化；现场需要立即止水时关闭上游水源，软件停止不等于机械阀已确认关闭。硬件范围、配置有效范围与安全时序沿用本文件其他章节。
