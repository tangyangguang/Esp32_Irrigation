## 当前产品边界

- 产品是一块本地运行的单板控制器，直接管理 6 个 12V DC 电磁阀区域；同一时刻最多打开一个区域。
- 默认启用区域 1、区域 2，区域 3 至区域 6 默认停用；用户可修改区域名称和启用状态。
- 流量计固定接入，所有出水过程都保留无流量保护；各区域独立管理用于流量异常判断的基准流量。
- 自吸泵功能可选，控制器只通过干接点信号控制外部继电器模块，不能确认泵是否真实启动。
- 最多保存 8 个每日浇水计划，每个计划最多设置 4 个启动时间；计划的自动执行开关不影响手动使用。
- 全部自动计划可统一暂停并定时或手动恢复；手动浇水不受该暂停状态影响。
- 阀默认全功率吸合 3 秒，随后以 20 kHz、75% 占空比维持，参数可在方案规定的范围内配置。
- WiFi、Web、认证、OTA、文件系统、系统日志、时间、RTC 和 MQTT 生命周期等公共能力使用`../../../../foundation/Esp32Base`；本项目只实现浇水业务和当前型号的协议映射。
- 本地浇水历史与平台补发共用 watering Store；必要审计使用独立 irrigation-audit Store。持续条件只保存当前状态，技术日志归基础库。每条记录流的累计 ACK 相互独立。

## 当前实现状态

当前固件已有本地业务、本地 Web、RTC 自动调度及直接 MQTT 外围适配，共用同一业务状态机。双 Store 与紧凑记录已实现，SDK、完整 TLS 和最新诊断接入仍待完成。最新版本、代码验证及剩余事项统一见 [固件说明](../../firmware/README.md)，不把旧版本 G4/G5 结果套用于新版本。MQTT 未配置、断开、重连或平台不可用不得改变本地 Web、RTC 调度、现场保护和安全停机能力。

实际硬件 RTC 已接通并测试正常。用户确认在统一 IoT 平台接入前已经使用真实水路验证六路阀门控制、流量计采集和流量校准，结果正常；这证明当时硬件与本地实现可用，但不替代之后代码修改完成后的当前版本回归。当前开发交付以固件 README 的定向检查为准；真实水路计量精度、长期运行和现场断电验证由用户按需安排，不作为本轮编码前置条件。专业校准已独立为后续任务；自吸泵只在实际安装使用时验收。

产品永久不实现 LCD2004、本地菜单和 4 个按钮业务交互。日常控制与进度使用本地 Web 和最终接入后的微信小程序；现场紧急止水使用上游水源开关，并可同时关闭控制器电源。板载 `LED1 / GPIO13` 作为低电平点亮的设备状态灯纳入当前固件。
