## 当前产品边界

- 产品是一块本地运行的单板控制器，直接管理 6 个 12V DC 电磁阀水路；同一时刻最多打开一个水路。
- 默认启用水路 1、水路 2，水路 3 至水路 6 默认停用；用户可修改水路名称和启用状态。
- 流量计固定接入，所有出水过程都保留无流量保护；各水路独立管理用于流量异常判断的基准流量。
- 自吸泵功能可选，控制器只通过干接点信号控制外部继电器模块，不能确认泵是否真实启动。
- 最多保存 8 个每日浇水计划，每个计划最多设置 4 个启动时间；计划的自动执行开关不影响手动使用。
- 全部自动计划可统一暂停并定时或手动恢复；手动浇水不受该暂停状态影响。
- 阀默认全功率吸合 3 秒，随后以 20 kHz、75% 占空比维持，参数可在方案规定的范围内配置。
- WiFi、Web、认证、OTA、MQTT/TLS、文件系统、系统日志、时间和 RTC 等公共能力使用 [Esp32Base](../../../../foundation/Esp32Base/README.md)；主固件固定使用 IOT Profile，本地灌溉业务与 IoT 平台/微信小程序接入并存，共用同一执行链路。
- 本地浇水历史使用 watering Store，必要操作历史使用独立 irrigation-audit Store，均按字节预算分段滚动，不受平台同步或 ACK 限制。持续条件只在 RAM 保存当前状态，技术日志归基础库，文件日志保持原实现。

## 当前实现状态

主固件固定为 IOT Profile：本地业务、Web、RTC 自动调度与 MQTT 平台接入共用同一执行链路。核心重构、原有页面风格恢复与 IoT 平台对接的主机实现均已完成：MQTT 适配按 `platform/iot-device` 的 irrigation-controller v1.3.0 契约重写，覆盖连接、8 类状态投影、5 类命令闭环和双可靠记录流；native 79/79 与 iot-device 全量检查通过，主 IOT 固件链接通过。真机 TLS/MQTT、小程序联调与物理动作待授权。当前交付状态、构建产物和验证边界统一见 [固件说明](../../firmware/README.md)，旧版本平台验收不作为当前版本证据。

实际硬件 RTC 已接通并测试正常。用户确认在统一 IoT 平台接入前已经使用真实水路验证六路阀门控制、流量计采集和流量校准，结果正常；这证明当时硬件与本地实现可用，但不替代之后代码修改完成后的当前版本回归。当前开发交付以固件 README 的定向检查为准；真实水路计量精度、长期运行和现场断电验证由用户按需安排，不作为本轮编码前置条件。专业校准已独立为后续任务；自吸泵只在实际安装使用时验收。

产品永久不实现 LCD2004、本地菜单和 4 个按钮业务交互。日常控制与进度使用本地 Web 和最终接入后的微信小程序；现场紧急止水使用上游水源开关，并可同时关闭控制器电源。板载 `LED1 / GPIO13` 作为低电平点亮的设备状态灯纳入当前固件。
